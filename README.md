### 一、AI编程提示词（精细化、可直接复用）
#### 提示词1：多源异构数据接入模块开发
```
角色：资深大数据工程师
任务：开发多源异构数据接入核心模块，要求如下：
1. 技术栈：Python + FastAPI + SQLAlchemy + pandas
2. 核心功能：
   - 支持MySQL、Doris数据库接入：实现通用数据库连接池，支持增量/全量数据抽取，可配置抽取频率（定时任务）；
   - 支持CSV/Excel文件接入：解析不同编码（UTF-8/GBK）、不同格式（多sheet、表头行自定义）的文件，校验文件完整性；
   - 统一数据接入接口：输出标准化DataFrame格式，记录数据接入日志（来源、时间、数据量、状态）；
   - 异常处理：连接失败重试、文件解析错误告警、数据量突变检测。
3. 代码要求：模块化设计，注释清晰，包含单元测试用例，符合PEP8规范。
请输出完整代码（含配置文件、核心逻辑、测试代码），并说明部署依赖和使用示例。
```

#### 提示词2：数据质量规则引擎开发
```
角色：数据质量专家 + 全栈工程师
任务：开发数据质量规则引擎，要求如下：
1. 技术栈：Python + 规则引擎（pyruleengine） + 企业微信/QQ邮箱SDK + Redis（缓存规则）
2. 核心功能：
   - 规则定义模块：支持可视化配置（输出JSON配置模板）唯一性（主键重复）、完整性（空值率）、一致性（字段值域匹配）、准确性（数值越界）规则；
   - 规则执行模块：支持批量/实时数据校验，可配置校验频率，输出质量报告（异常数据量、异常率、异常明细）；
   - 告警模块：当异常率超过阈值时，自动触发企业微信/QQ邮件告警，包含异常详情和定位链接；
   - 适配场景：主数据（客户信息）、交易数据（订单流水）、指标数据（营收指标）。
3. 输出要求：核心代码 + 规则配置示例 + 告警触发流程说明 + 性能优化建议。
```

#### 提示词3：元数据管理与血缘分析模块开发
```
角色：数据架构师 + 后端工程师
任务：开发元数据管理和血缘分析模块，要求如下：
1. 技术栈：Java（SpringBoot）/Python + Neo4j（图数据库） + ECharts（可视化）
2. 核心功能：
   - 元数据采集：自动抓取MySQL/Doris表结构、字段类型（技术元数据），支持手动录入数据定义、业务归属（业务元数据）；
   - 血缘分析：追踪数据从源头（数据库/文件）→ 转换（ETL）→ 应用（报表/指标）的完整链路，支持正向（字段修改影响哪些报表）和反向（报表异常根因定位）分析；
   - 数据字典：统一管理业务术语（如“有效订单”）、指标口径（如“月均营收=月营收/天数”），支持检索和版本管理；
   - 数据地图：可视化展示所有数据资产的归属、关联关系、质量状态。
3. 输出要求：模块设计架构图 + 核心代码（元数据采集、血缘存储） + 数据地图可视化示例 + 部署注意事项。
```

3. 输出要求：权限模型设计图 + 核心代码（权限校验、日志记录） + 审计日志查询示例 + 安全合规建议。

### 二、项目建设规划（分阶段落地，可落地性优先）
#### 阶段1：基础搭建期（1-2个月）
**核心目标**：完成多源数据接入和基础ETL能力搭建，实现数据“能进来、能处理”
1. 环境部署：
   - 搭建基础技术栈：Python/FastAPI（数据接入）、MySQL（基础存储）、Apache Superset（初步可视化）；
   - 配置数据库连接池、文件存储目录（NFS），完成权限初始化（基础RBAC角色）。
2. 核心开发：
   - 开发MySQL/Doris、CSV/Excel数据接入接口，实现全量数据抽取；
   - 开发简易ETL工具链：支持SQL脚本清洗、Python脚本转换，提供可视化拖拽式流程编辑（基于Airflow/ETLBox）；
   - 完成数据接入日志和基础监控（任务是否执行成功）。
3. 验收标准：
   - 能成功接入至少2类数据库+2类文件数据，数据抽取准确率100%；
   - ETL脚本可完成基础清洗（去重、空值填充），执行成功率≥99%。

#### 阶段2：能力完善期（2-3个月）
**核心目标**：补齐数据质量、元数据管理能力，实现数据“管得好、可追溯”
1. 核心开发：
   - 开发数据质量规则引擎：支持唯一性、完整性、一致性校验，配置异常阈值和告警规则（企业微信/QQ邮件）；
   - 开发元数据采集模块：自动抓取技术元数据，手动录入业务元数据，搭建基础数据字典；
   - 完善细粒度权限控制：实现表/字段级权限，开发审计日志模块（记录查询/导出操作）。
2. 集成优化：
   - 优化ETL工具链：支持ELT模式（先加载后转换），适配Doris数仓特性；
   - 接入实时监控：对数据空值率、数值越界、接入延迟进行实时检测，触发告警。
3. 验收标准：
   - 数据质量规则覆盖率≥80%（覆盖主数据/交易数据），异常检测准确率≥95%，告警响应时间≤5分钟；
   - 元数据采集覆盖率≥90%，数据字典可检索，权限控制无越权访问案例。

#### 阶段3：深化应用期（2-3个月）
**核心目标**：完成血缘分析、可视化分析，实现数据“可追溯、能分析”
1. 核心开发：
   - 开发血缘分析模块：基于Neo4j构建数据血缘图谱，支持正向/反向分析，实现影响分析和根因定位；
   - 完善数据地图：可视化展示数据资产、血缘关系、质量状态；
   - 深化可视化分析：集成DataEase/Apache Superset，开发交互式报表和任务监控面板；
   - 优化权限控制：实现行级权限和动态权限过滤，审计日志支持多维度检索。
2. 试点验证：
   - 选取1-2个业务场景（如订单数据全链路管理）进行端到端验证，优化流程和功能；
   - 收集业务侧反馈，调整数据质量规则、元数据定义、可视化报表。
3. 验收标准：
   - 血缘分析覆盖100%核心数据链路，影响分析准确率≥98%；
   - 交互式报表支持钻取/筛选，监控面板实时刷新（延迟≤1分钟），用户满意度≥90%。

#### 阶段4：运维优化期（1个月）
**核心目标**：系统稳定运行，形成标准化运维体系
1. 运维建设：
   - 制定数据接入、质量校验、元数据管理的标准化流程；
   - 搭建系统监控面板：监控服务器资源、任务执行效率、告警触发频率；
   - 完善容灾备份：数据定期备份、任务失败自动重试、异常快速恢复。
2. 培训与交付：
   - 对运维人员、业务人员进行操作培训（数据接入、规则配置、报表使用）；
   - 输出用户手册、运维手册、应急处理预案。
3. 验收标准：
   - 系统7×24小时稳定运行，故障率≤0.5%；
   - 所有功能模块文档齐全，人员培训覆盖率100%。

### 三、项目保障措施
1. 团队配置：大数据工程师（2-3人）、全栈工程师（1-2人）、数据质量专家（1人）、业务顾问（1人）；
2. 技术选型原则：优先选用开源成熟组件（如Superset、Neo4j），减少自研成本，降低维护难度；
3. 迭代方式：采用敏捷开发，2周一个迭代，每个迭代输出可测试的功能，及时收集反馈调整。

### 总结
1. AI编程提示词聚焦**模块化开发**，按“数据接入→质量管控→元数据管理→权限审计→可视化”拆分，明确技术栈、核心功能和输出要求，可直接用于生成代码；
2. 项目建设规划分4个阶段（基础搭建→能力完善→深化应用→运维优化），从“能接入”到“能管理、能分析”逐步落地，兼顾可落地性和业务价值；
3. 核心目标始终围绕“多源数据统一管理、数据质量可控、数据资产可追溯、分析能力可用”，覆盖数据集成→管理→分析全链路。
